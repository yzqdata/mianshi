一、Java 基础

Q1 ==和equals的区别

==:

  • ① 基本类型，则比较的是基本类型中存储的数值是否相同。相同则返回true，不同则返回false;
  • ② 引用类型，则比较的两个引用类型的地址，地址相同，则返回true，地址不同则返回false。

equals:

  • 作用：比较两个引用类型的内容是否相等的。
  • 注意：在自己的模板中需要对equals方法进行重写，因为从Object继承的equals方法底层使用的==比较。

使用场景:

  • ① 基本类数据比较使用==
  • ② 如果引用类型比较内容是否相等，则调用其自己的equals方法
  • ③ 如果比较两个引用类型是否是同一个对象，则使用==;

Q2 final finalize finally

final修饰不可变 修饰的class不可以继续扩展继承，方法不可以重写， 变量不可以修改

finally，异常总被执行的

finalize objecct里面的关键字，一个方法，用于在对象消失时，由jvm进行调用用于对对象进行垃圾回收

在垃圾收集器执行的时候会调用被回收对象的此方法，供垃圾收集时的其他资源回收，比如关闭文件

Q3 面向对象的三大特征

  • 封装，继承，多态
  • 继承， 是子对象可以继承父对象的属性和行为，就是父对象拥有的属性
  • 多态，允许不同类的对象对同一消息作出响应

Q5 转换成文字

问题：请介绍一下集合、请介绍一下你知道的容器、请介绍一下集合的继承结构？

集合中分为两大类。一个是Collection接口和Map接口。

Collection接口的子接口有List接口存储有序可重复数据和Set接口存储无序不可重复数据。

List接口常用实现类有ArrayList可变长度数组和LinkedList链表结构和线程安全的可变长度数组Vector

Set接口常用实现类有HashSet和TreeSet，HashSet底层是HashMap，HashSet中的值作为HashMap的key，new Object作为HashMap的value。TreeSet底层是TreeMap，TreeSet中的值作为TreeMap的key，new Object作为TreeMap的value。

另一大类Map存储的是key-value类型，常用实现类有HashMap哈希表、Treemap红黑树、HashTable。

从Java5以后推出JUC包含了一些线程安全的容器。如：ConcurrentHashMap等。

衍生出来的问题：

Q6 ArrayList如何可变的？ArrayList底层的数组是怎么变长的？

答：当元素个数超过ArrayList的长度时，使用Arrays.copyOf把原数组长度扩大1/2，放到一个新的数组。

Q7 ArrayList 和LinkedList区别？

ArrayList适合做查询操作。因为是内存的一块连续空间。

LinkedList适合做新增和删除。因为底层是链表结构。

Q8 HashMap底层原理？（特别常见面试问题）

  • 答：从Java8开始HashMap底层由数组+链表变成数组+链表+红黑树。

使用HashMap时，当使用无参构造方法实例化时，设置扩容因子为默认扩容因子0.75。

当向HashMap添加内容时，会对Key做Hash计算，把得到的值对Hash表长度取余，定位到Hash的位置。把内容添加到对应的链表或红黑树中。

如果添加后链表长度大于等于8，会判断Hash表长度是否大于64，如果小于64对Hash扩容，扩容长度为原长度的2倍，扩容后把原Hash表内容重新放入到新Hash表中。如果Hash长度大于等于64会把链表转换红黑树。

最终判断HashMap中元素个数是否已经达到扩容值(threshold)，如果达到扩容值，需要进行扩容，扩容一倍。

反之，如果删除元素后，红黑树的元素个数小于6，由红黑树转换为链表。

Q9 Java 7 和Java 8 的HashMap区别？

  • Java 7 数组+链表 java 8 数组+链表+红黑树
  • Java 7 链表数据尾插法。新增数据放在链表的最后。 Java 8 链表数据头插法。新增数据放入到链表的第一个位置

Q10 Vector和ArrayList的区别？

答：Vector大部分方法都使用synchronized关键字修饰，是线程安全的。在多线程下性能要低于ArrayList。

Q11 HashMap和HashTable的区别？

答：Hashtable 是线程安全的，HashTable不允许key为null，HashMap允许key为null。

Q12 什么是JUC？

答：从java5推出的一个包，java.util.concurrent包。里面所有内容统称JUC。

JUC包含五大功能：原子类、Lock、并发集合、工具类、线程池。

Q13 ConcurrentHashMap的底层原理？ConcurrentHashMap如何保证的线程安全？

答：通过synchronized和cas算法实现的线程安全。

java 7 和java 8 中Concurrent HashMap的区别？

  • 使用synchronized代替Segment分段锁，实现更加简单。
  • Java8中HaspMap是链表+红黑树，java7中长链表，查询效率更快了。
  • 使用synchronized代替ReentrantLock，在锁竞争不激烈情况下，性能相差不大。

Q14 什么是重入锁？Java 通过如何实现的重入锁？（外包公司常见）

重入：在线程中如果锁已经被其他人持有，是否能够再次获取到锁。如果能够再次获取叫做重入锁，如果不能再次获取叫做非重入锁。

通过ReentrantLock实现的重入锁。

Q15 请介绍下什么是红黑树？（外包公司）

前提条件：必须是二叉查找树（不为空的情况下，左边必须比根节点小，右边必须大）

  • 所有节点必须是红色或黑色
  • 根节点必须是黑色
  • 所有叶子节点必须是黑色。
  • 红色节点下面必须是两个黑色节点。
  • 任意节点到达叶子节点所包含的黑色节点数量是一样的。

Q16 请说一下什么是ACID/请说一下事务的四大基本原则？

ACID：A是原子性：要不就成功，要不就失败。 C：一致性：数据操作是一致的。 I：隔离性。数据库的隔离级别 D：持久性。数据操作结果持久保存。

Q17 什么是Hash碰撞？如何解决Hash碰撞？（常见面试题）

Hash碰撞：不同的内容得到相同的Hash结果。

解决办法：

  • 链式地址法。Hash表中存储链表头地址。当碰撞后，存储到对应链表中。
  • 开放定址法。碰撞后，定位到下一个Hash表位置。
  • 再次Hash法。如果碰撞，对结果再次Hash计算。
  • 公共溢出区。除Hash表外，额外建立溢出区，碰撞后放入到溢出区。

Q18 线程生命周期（常见面试题）

线程分为五种状态：新建状态、就绪状态、运行状态、阻塞状态、死亡状态。

当新建线程对象时，线程处于新建状态。线程对象调用start()方法后线程切换为就绪状态。就绪状态是临时状态，只要线程获取到CPU执行权限，会自动切换为运行状态。

处于运行状态的线程分为多种情况：

  • 如果运行时使用线程对象调用yield()，切换状态为就绪状态。如果就绪状态的线程能获取到CPU权限，自动切换为运行状态。
  • 如果运行时使用Thread.sleep()使线程休眠，线程会切换为阻塞状态。休眠时间结束后，自动切换为就绪状态。
  • 如果运行时使用suspend()暂停线程，线程会切换阻塞状态。等待调用resume()后才能切换为就绪状态。如果一直不调用resume(),可能出现死锁问题，因为suspend()不释放锁。
  • 如果运行时使用wait()暂停线程，线程会切换为阻塞状态。调用notify()/notifyAll()或超出wait()最大等待时间，线程会切换为就绪状态。因为wait会释放锁，所以不用担心死锁问题。
  • 如果运行时使用join()把其他线程加入到当前线程，会把当前线程挂起，切换为阻塞状态。等待加入的线程执行完成，自动切换为就绪状态。
  • 如果运行时使用stop()强制停止，线程会立即停止，线程切换为死亡状态。
  • 如果线程成功运行结束，切换为死亡状态。
  • 如果线程运行中出现Exception或Error，且没有处理，线程切换为死亡状态。

为了防止线程长时间处于阻塞状态。可以使用interrput()中断线程。中断后会抛出InterrupedException。

Q19 wait()和sleep()的区别(经典面试题)

  • 所属类不同。wait() 是Object中方法。sleep()是Thread的方法。
  • 唤醒机制不同。wait() 在没有设置最大时间情况下，必须等待notify。sleep是到指定时间自动唤醒。
  • 使用位置不同。wait()必须持有对象锁。sleep()可以使用在任意地方。
  • 方法类型不同。wait()是实例方法。sleep()是静态方法。
  • 锁机制不同。wait()释放锁。sleep()只是让线程休眠，不会释放锁。

Q22 线程池拒绝策略？（最近面试问的频率较高）

  • 先要明白什么时候拒绝（已经到达最大线程数，队列也满了。还要获取线程对象时，启用拒绝策略）

Q23 lock和synchronized的区别（常见面试题）（至少记住4点，必须记住两点必须被包含）

  • 类型不同。synchronized是关键字，Lock是接口
  • （必须记）加锁和解锁机制同步不同。synchronized是自动加锁和解锁，程序员不需要控制。Lock必须由程序员控制加锁和解锁过程
  • 异常机制不同。synchronized碰到没有处理的异常，会自动解锁，不会出现死锁。Lock碰到异常不会自动解锁，可能出现死锁。所以写Lock锁时都是把解锁放入到finally中。
  • Lock功能更强大。Lock里面提供了tryLock()/isLocked()方法，进行判断是否上锁成功。synchronized因为是关键字，所以无法判断。
  • （必须记）Lock性能更优。如果多线程竞争锁特别激烈时，Lock的性能更优。如果竞争不激烈，性能相差不大。
  • 线程通信方式不同。synchronized 使用wait和notify线程通信。Lock使用Condition的awake和signal通信。
  • 暂停和恢复方式不同。synchronized 使用suspend和resume暂停和恢复，这俩方法过时了。Lock使用LockSupport中park和unpark暂停和恢复，这俩方法没有过时。

Q24 了解：synchronized底层原理。

在Java早期，synchronized叫做重量级锁，加锁过程需要操作系统在内核态访问核心资源，因此操作系统会在用户态与内核态之间切换，效率很低下。于是JDK1.6之后，JVM为了提高锁的获取与释放效率，对synchronized进行了优化，引入了偏向锁和轻量级锁，根据线程竞争情况对锁进行升级，在线程竞争不激烈的情况避免使用重量级锁。

无锁：对象头中有31bit的空间来存储对象的hashcode，4bit用于存放对象分代年龄，1bit来表示是否是偏向锁，2bit存放锁标志位，偏向锁位与锁标志位合起来“001”就代表无锁。无锁就是没有对任何资源进行锁定，所有线程都能访问并修改资源。

偏向锁：对象头中记录了获得偏向锁的线程ID，偏向锁与锁标志位合起来“101”就代表偏向锁。有研究发现，在大多数情况下，锁很少被多个线程同时竞争，而且总是由同一个线程多次获得，因此只需要将获得锁的线程ID写入到锁对象Mark Word中，相当于告诉其他线程，这块资源已经被我占了。当线程访问资源结束后，不会主动释放偏向锁，当线程再次需要访问资源时，JVM就会通过Mark Word中记录的线程ID判断是否是当前线程，如果是，则继续访问资源。所以，在没有其他线程参与竞争时，锁就一直偏向被当前线程持有，当前线程就可以一直占用资源或者执行代码。

自旋锁（轻量级锁）：一旦有另外一个线程参与锁竞争，偏向锁就会升级为自旋锁，此时撤销偏向锁，锁标志位变为“00”。竞争的两个线程都在各自的线程栈帧中生成一个Lock Record空间，用于存储锁对象目前Mark Word的拷贝，用CAS操作将Mark Word设置为指向自己这个线程的LR（Lock Record）指针，设置成功者获得锁，其他参与竞争的线程如果未获取到锁，则会一直处于自旋等待的状态，直到竞争到锁。

重量级锁：长时间的自旋操作是很消耗CPU资源的，为了避免这种盲目的消耗，JVM会在有线程超过10次自旋，或者自旋次数超过CPU核数的一半（JDK1.6以后加入了自适应自旋-Adaptive Self Spinning，由JVM自己控制自旋次数）时，会升级到重量级锁。重量级锁底层是依赖操作系统的mutex互斥锁，也就是有操作系统来负责线程间的调度。重量级锁减少了自旋锁带来的CPU消耗，但是由于操作系统调度线程带来的线程阻塞会使程序响应速度变慢。

在markword中标记锁的类型

普通对象在内存中的结构分为多部分，第一部分称为markword，共64位。在对应锁对象的markword字段的低位字段标记锁的类型。

  • 网络接口层或网路链路层。合并了OSI数据链路层、物理层。实现数据向传输介质的传递和接收以及检查和纠正。

Q27 TCP和UDP的区别？

  • 连接方式不同。TCP需要建立连接。UDP是无连接的。
  • 数据完整性不同。TCP是可靠的。UDP是不保证数据完整性的。
  • 数据内容类型不同。TCP是字节流。UDP是报文，即对字节数据的再次封装。
  • 可接收目标主机数量不同。TCP是标准的点对点。UDP可以是一对一，一对多，多对多数据传输。
  • 首部开销不同。TCP首部开销20字节。UDP首部开销8字节。
  • 传输效率不同。UDP要比TCP传输效率更高。

Q28 TCP三次握手建立连接流程（面试题）

第一次握手：客户端向服务器端发送消息，包含SYN=1希望创建连接，和Seq=X的序列值。

第二次握手：服务端向客户端发送消息，包含SYN=1表示连接，和ACK=X+1表示接收到了连接的请求，和Seq=Y重列序列值。表示同意建立连接。

第三次握手：客户端向服务端发送消息。包含ACK=Y+1接收到服务端同意答复，Seq=Z重置序列值。

之后建立上连接了。

Q29 TCP四次挥手断开连接的流程（面试题）

第一次挥手：主动方向被动方发送消息。包含Fin=1希望断开连接，ACK=Z希望应答值，Seq=X序列值。表示希望断开连接。

第二次挥手：被动方向主动方发送消息。ACK=X+1表示接收到断开请求，Seq=Z设置序列值。这次挥手只是告诉主动方，知道了主动方希望断开连接。

第三次挥手：被动方向主动方发送消息。被动方处理完所有事情以后，告诉主动方可以断开连接连接了。包含Fin=1，ACK=X，Seq=Y

第四次挥手：主动方向被动方发送消息。包含ACK=Y，Seq=X。表示都可以断开连接了，释放资源。

Q30 String、StringBuffer、StringBuilder的区别？（）

底层数组修饰符不同：String、StringBuffer、StringBuilder底层都是char数组。但是String数组使用final修饰，是常量数组。

内存存储位置不同：String在字符串常量池中（Java8字符串常量池在堆中），StringBuffer和StringBuilder存在堆中。

线程安全不同：StringBuilder是非线程安全的，StringBuffer是线程安全的。

效率不同：StringBuilder性能高于StringBuffer

使用场景：如果字符串内容不变使用String，可变字符串且单线程时使用StringBuilder，可变字符串在多线程环境下使用StringBuffer

Q31 乐观锁和悲观锁？

乐观锁：认为不需要加锁也能保证线程安全。CAS是乐观锁。

Q33 BIO、NIO、AIO的区别？（面试题）

BIO：是Blocking I/O,同步阻塞IO。服务端内部代码会阻塞当前线程，所以是同步的。多线程访问时，默认只能处理一个，所以是阻塞的。

  • 可以通过多线程和线程池实现多线程访问。因为是多线程带来系统资源消耗、线程切换性能消耗的问题。

BIO是JDK1.4之前唯一的IO模型。

NIO：称为New IO或Non-Blocking IO。同步非阻塞IO。从JDK1.4推出的。在线程内部依然是同步的。但是可以是单一线程处理多线程访问，所以非阻塞的。

有效解决了BIO因为多线程带来的资源消耗和性能切换导致的性能消耗问题。

Tomcat 7 开始默认就是NIO模型。

AIO：asynchronous IO，称为异步非阻塞IO。从JDK 1.7推出的。有两种实现方案，一种通过Future实现，一种通过CompletionHandler回调机制实现的。

Q34 CAS？

Compare And Swap 比较和交换算法。

思路：

  • 创建副本
  • 计算最终需要设置的值
  • 比较副本值是否和内存值相等。
  • 1 如果相等，修改内存值为需要设置的值。
  • 2 如果不相等，重新创建副本，重新执行全套流程（循环）

Q35 JVM内存结构？（特别常见面试题）

JVM按照规范分为：堆、方法区、虚拟机栈、本地方法栈、程序计数器。

其中堆存放对象或数组信息，里面分为新生代和老年代。实例化的对象放入到新生代中。如果是大对象，直接放入老年代。

方法区在Java7中使用永久代作为具体实现，永久代和老年代是一块连续空间。在Java8中使用元空间作为具体实现，元空间放入到直接内存中。里面存放类相关的信息。

虚拟机栈不是线程共享的，每个方法运行会在里面产生一个栈帧。存放方法的全部信息。

本地方法栈负责native修饰的方法。

程序计数器每个线程一块空间，存放执行到的行号。

Q36 GC分类/GC的种类/ JVM支持的垃圾回收有几种？

单线程收集器：Serial和Serial Old。

Serial升级版多线程收集器：ParNew

两个并发收集器：Parallel 和Parallel Old

老年代收集器CMS

CMS的替代G1回收器。

简易回答：两个单线程收集器，两个并发收集器。新生代的多线程收集器。CMS和G1收集器。

Q37 GC算法有几种？

标记清除算法。先标记，把标记的内容清除。但可能有内存碎片。

复制算法。把不可回收对象复制到另一个空间，再把当前空间全部清除。

标记整理算法。先标记，把标记内容清除。把剩余内容进行压缩整理

分代算法。目前JVM使用的是分代算法，分为新生代和老年代。每个代可以使用不同的算法。

Q48 配置声明式事务时，如何配置事务传播行为？/ 请说一下Spring支持的事务传播行为

通过propagation属性进行配置。

事务传播行为都是在多个具有事务控制的方法相互调用时才能出现的。

可取值有：

  • REQUIRED:默认值。如果当前有事务则加入到事务中。如果当前没有事务则新增事务。
  • NEVER:必须在非事务状态下执行,如果当前没有事务,正常执行,如果当前有事务,报错.
  • NESTED:必须在事务状态下执行.如果没有事务,新建事务,如果当前有事务,创建一个嵌套事务.
  • REQUIRES_NEW：必须在事务中执行,如果当前没有事务,新建事务,如果当前有事务,把当前事务挂起. 在重新建个事务。
  • SUPPORTS：如果当前有事务就在事务中执行,如果当前没有事务,就在非事务状态下执行.
  • NOT_SUPPORTED：必须在非事务下执行,如果当前没有事务,正常执行,如果当前有事务,把当前事务挂起.
  • MANDATORY：必须在事务内部执行,如果当前有事务,就在事务中执行,如果没有事务,报错.

前四行必须记住的。后面明确和面试官说，还有6个属性，有的需要在事务中执行，有的需要在非事务中执行。具体取值长时间没有使用记不住的。如果需要使用通过百度或开发手册看一眼即可。

Q59 缓存穿透（特别常见面试题）

Q60 布隆过滤器

1970年由布隆研究的一种算法和数据结构。

核心是对数据做N次不同的Hash计算。把得到的Hash值对数组长度取余。对应脚标位置修改为1.

如果下次查询时发现某个值的N个Hash值对应数组中某个脚标不为1，说明这个数据一定不存在。

  • 加锁。并发访问时使用锁让一个请求查询数据库。缺点：并发访问时性能较低。

Q62 缓存雪崩（特别常见面试题）

  • 自定义算法，设置所有key的有效时间不相同。尽可能的让每个key的实效实现错开。

Q63 淘汰策略

  • maxmemory-policy noeviction 默认策略noevication
  • maxmemory <bytes> 缓存最大阈值
  • volatile-lru → 在设置过期key集中选择使用数最小的。

  • volatile-lfu → 在设置过期时间key集中采用lfu算法。
